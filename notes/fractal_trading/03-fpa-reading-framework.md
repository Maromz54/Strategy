# שיעור 03 — Fractal Price Action Reading Framework

מקור: `transcripts/L003_Fractal_Price_Action_Reading_Framework.json` · global 77

## תקציר

הארכיטקטורה של כל השיטה. **זה השיעור שממפה ישירות לארכיטקטורת הבוט.**

נקודת מוצא: נרות אינם price action — הם **ייצוג** של price action. לכן צריך לפרש אותם.

## שלוש השכבות

מוצג בשיעור כשלושה מעגלים קונצנטריים (01:28 בתיאורי המסך):

```
┌─ Fractal Analysis ────────────────────┐   ← השכבה החיצונית, כורכת את השתיים
│  ┌─ Extrinsic Forces ─────────────┐   │      הפנימיות; מובנת רק בסוף הקורס
│  │  ┌─ Intrinsic Properties ─┐    │   │
│  │  │  absolute / relative   │    │   │
│  │  └────────────────────────┘    │   │
│  └────────────────────────────────┘   │
└───────────────────────────────────────┘
   broad → הקשר          narrow → דיוק ותזמון
```

### שכבה 1 — Intrinsic Properties (תכונות פנימיות של הנר)

| מצב | הגדרה |
|---|---|
| **absolute terms** | ניתוח נר **בודד בבידוד** |
| **relative terms** | איך התכונות **משתנות/מתפתחות** מנר לנר |

הרשימה כפי שהוצגה על המסך (00:30): `Body Size`, `Range`, `Upper Shadow`, `Lower Shadow`,
`Body%`, `Bias/Sentiment`, `Shadow Symmetry / Body Position`.

> אזהרה מהמבחן (שיעור 4, שאלה 1): **volume אינו** תכונה פנימית של נר. volatility (range) כן.

### שכבה 2 — Extrinsic Forces (כוחות חיצוניים)

כוחות שוק שמ**שנים** את הפרשנות שהתקבלה מהתכונות הפנימיות. אותו נר בדיוק אומר דבר אחד
בבידוד ודבר אחר בהקשר. ארבעת הכוחות כפי שהוצגו (01:32):

1. `Location or Trend Phase`
2. `Overextension`
3. `Price Barriers`
4. `Prior Price Action Activity`

### שכבה 3 — Fractal Analysis

כורכת את השתיים. השיעור מודה מראש שאי אפשר להבין אותה עכשיו — רק בסוף הקורס.

## אנלוגיית השפה

```
אותיות  →  מילים        →  משפטים       →  פסקאות  →  נרטיב
נרות    →  price vectors →  highs / lows →  broad price action
```

כמו שמפרשים מילה לאור ההקשר, מפרשים נר לאור מבנה רחב יותר. המטרה המוצהרת: לזהות את
**הנרטיב בין קונים למוכרים**.

## עמדה מתודולוגית

השיטה **דוחה** שינון תבניות נרות יפניות (hammer, doji, engulfing וכו') כשיטת עבודה.
הטענה: ללמוד תכונות וכוחות קל יותר ועובד טוב יותר מלשנן עשרות תבניות מוכנות. הסיבה
המהותית — תבנית מוכנה חסרת הקשר, וההקשר הוא שקובע את המשמעות.

## חוקים ניתנים לקידוד

**זו למעשה מפרט הצנרת (pipeline) של הבוט:**

```
OHLC bar
   ↓
[1a] intrinsic_absolute(bar)          → dict של תכונות הנר הבודד
[1b] intrinsic_relative(bar, prev…)   → דלתאות והתפתחות
   ↓
[2]  extrinsic_context(bar, history)  → {trend_phase, overextension,
                                          barriers, prior_activity}
   ↓
[3]  fractal_layer(...)               → כריכה רב-סקאלתית
   ↓
decision: trigger / stop / target
```

הסדר אינו שרירותי: שכבה 2 **מודולציה** על פלט שכבה 1, לא מסנן נפרד אחריה. כלומר
הפרשנות של הנר צריכה להיות פונקציה של ההקשר, ולא `if signal and context_ok`.
זו הבחנה משמעותית לתכנון, ואצטרך לחזור אליה בשיעורים 9-10.
